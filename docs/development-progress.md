## 当前验证与边界

- **主城与出阵**。负责人已验收主城层级、出阵拖动和绿勾。独立角色在 Creator 浏览器预览验证了特效上方的召唤入口可点击，以及出阵自动入位、跨排移动、占位交换、锁位与无效回位、保存后重开。阵型迁位和新增 UI 层顺序由客户端专项覆盖。[阵容页面](formation-ui-authoring.md) · [界面架构](architecture.md)
- **契约阵型**。Creator 本机预览使用两个独立角色，检查了八套阵型横向浏览、锁定项条件与普通格加成、共享模态空白关闭。已解锁角色从起源切换到逆转，三名英雄由 2、3、5 位迁至 1、2、3 位。未出阵关窗重开回到原阵型，点出阵后收到保存回执，重新打开保留新阵型。[阵容页面](formation-ui-authoring.md)
- **元素抑制与队伍光环**。使用独立角色验证五向克制、六组档位、激活置顶与空白关闭。两名火系生命和攻击各加 3%，三名各加 5%，跨排拖动时保持三人档，逐名撤下时退回两人档并清除激活。专项校验跨组叠加、五元素混合和助战排除。[阵容页面](formation-ui-authoring.md)
- **免费首抽与普通新号首战**。关闭 GM 的独立内存服中，从零名册通过主城召唤法阵获得四星一级布兰特，召唤积分 1 静默到账。只用该英雄出阵并完成第1关，通关后实际领取挂机宝箱。重登保留英雄、关卡和资产，已完成的免费按钮隐藏。后端及客户端联调验证原键重放、并发防重、满容量、回滚和重登恢复。布兰特普攻和一级主动的32张帧按旧图集恢复，原 UUID 保留。两段旧技能音频源文件尚缺。[通信契约](network-contract.md) · [原图核验](validation/chapter-first-summon-assets-20261118.json)
- **独立通关奖励与精英碎片合成**。关闭 GM 的独立内存服和 Creator 本机预览中，新号首通第1关后从「通关奖励」领取 `1001001`、`1002001` 各一件，通关红点消失。首次结算发放的 `20204004 ×30` 通过背包「使用」合成四星缇芮，碎片扣清，名册从1名增至2名。冷重登核对英雄和装备数量。重复请求、原回执和多次合成由专项检查覆盖，数量选择窗尚未单独做实际预览。[通信契约](network-contract.md) · [配置来源](config-pipeline.md#独立通关奖励与精英碎片)
- **普通英雄升级**。关闭 GM 的独立内存服和 Creator 本机预览中，首战的4000金币与500英雄经验让一级布兰特一次升5级，再一次升4级。两笔分别扣410金币/105英雄经验、1028金币/296英雄经验，余2562金币与99英雄经验。详情属性实时刷新，经验不足标红并显示飘字，重登保留10级与扣费结果，继续使用10级布兰特通过第2关。本机预览检查了升级结果与排版，升级光效逐帧时序、上限、丢回包、丢推送和换号迟到靠专项检查覆盖。V32 通过 H2 迁移检查，目标 MySQL 待验证。[升级维护](hero-lineup-contract.md#普通英雄升级)
- **主线与奖励**。独立 H2 从第1关连续挑战、结算到第20关。Creator 播放第10～20关真实样本，独立角色通过第15关领取英雄一次，冷重登无重复反馈，第16关切换地图。浏览器样本使用准备过的阵容。见 [检查](validation/chapter-stage10-20-review-20261117.json) 和 [本机记录](validation/chapter-stage10-20-preview-20261117.json)。
- **开场与技能台**。真实开始骨骼进度70%触发出场，出场第9个完整帧后模型渐入，底栏直接切换。F9目录实际识别47个精确技能等级，抽验玛蒙一级演示及关闭返回。见 [本机记录](validation/skill-audit-opening-navigation-review-20261117.json)。
- **挂机与恢复**。本机实际执行正常领取、断线后的待确认恢复和统一奖励反馈。客户端领取阈值65秒，服务端60秒。当前本机两服的开服资料来自各自外部配置，活动发布和环境配置见 [领取事务](main-chapter-idle-settlement.md) 和 [活动控制](idle-activity-maintenance.md)。
- **发布与环境**。已保留11月14日配置包真实构建的记录，随后玩法使用 Creator 本机预览。MySQL增量、正式CDN、原生平台、真机、物理弱网和异常退出仍需各自验证。见 [发布记录](validation/config-package-release-review-20261114.json)。

## 框架与维护入口

页面定义由各 View 的注册参数和对应 Prefab 持有。登录阶段按 LoadingPlan 加载少量启动配置，进入主城前安装一份 GameConfig 配置包，主城后预载常用界面，其余资源按需取得。资源引用归原资源池和页面生命周期。详见 [架构](architecture.md)、[资源加载](staged-resource-loading.md) 和 [交接入口](handoff.md#从哪里改)。
