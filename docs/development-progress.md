# 当前项目进度

截至 2026-11-23，初版七个底栏入口中，主城、英雄、背包、战斗、副本已有玩家可操作的页面。公会、VIP 仍缺业务入口。主城的召唤法阵和普通市场也已接通。下表按 hao 工作区现有实现统计，每一行单列玩法深度和缺口。[下一步计划](restructuring-plan.md)

**主城基础入口。** 召唤法阵支持基础、友情、高级各自的单抽与十连、积分兑换。祈愿购买依赖支付。普通市场可购买、限购、免费与付费刷新，紫色和金色精灵购买待实例规则恢复。[召唤与市场协议](network-contract.md)

**主线开放口径。** 850 是配置关数，550 是当前服务端默认挑战上限。11 月 20 日的静态扫描覆盖全部 850 关，前 550 关的守军、技能、资源与发奖依赖齐全。运行离线 Java 审计后可用 `node tools/audit_main_chapter_dependencies.cjs --from-java --write` 复查。实际连续挑战及 Creator 抽验见下方分批记录。[第 551 关映射分歧](battle-known-issues.md#当前未解决)

**挂机和运行环境。** 挂机从创角计时，行军、遇敌、对话与 850 关的产物配置已接入。领取在本机 local 默认启用，通用服务配置默认关闭。其他环境须提供可信开服时间和活动控制。[活动控制](idle-activity-maintenance.md)

## 框架与维护入口

召唤由 HeroRosterController 收发，碎片合成归 BagController，普通升级归 HeroLevelController，普通市场归 MarketController。MainChapterController 统一处理主线、挂机和通关领奖，IdleClaimBinding 负责宝箱点击与确认。RewardController 收发奖推送，RewardBinding 展示通用反馈。开发试战和 GM 发放分别归 BattlePreviewController、GmController。普通点击只发送一次，回包用于本次反馈，真实资产随统一快照更新。账号与连接层隔离旧回包，重连后通过鉴权首包恢复。布阵仍等待对应阵容版本，战斗结算仍使用服务端战斗编号。[开发交接](handoff.md#从哪里改)

客户端职责整理后已复跑碎片合成、独立通关奖励、挂机确认、里程碑、主线结算及冷重登等专项。

页面定义由各 View 的注册参数和对应 Prefab 持有。登录阶段按 LoadingPlan 加载少量启动配置，进入主城前安装一份 GameConfig 配置包，主城后预载常用界面，其余资源按需取得。资源引用归原资源池和页面生命周期。详见 [架构](architecture.md)、[资源加载](staged-resource-loading.md) 和 [交接入口](handoff.md#从哪里改)。
