# 六个核心流程的还原验收清单

更新：2026-11-02。目标为旧游戏 1:1；这六项是当前工作顺序，不代表最终只恢复这些功能。原版版本与模块索引见 [源码证据](validation/architecture-source-index-20261102.json)，整体缺口见 [当前进度](development-progress.md)。

证据分为：源码确认、历史画面观察、本轮实际复验。以下本轮实际复验均为“未进行”，不能用自动化通过替代视觉验收。正式服用已授权 hao1 账号；不同账号等级/资产造成的开放状态差异须单独记录，不直接判 UI 错误。不对照新手流程，但最终创角与新手规则仍需恢复。

| 流程 | 原版依据与要比的内容 | 当前状态/已知缺口 | 下一次验收动作 |
|---|---|---|---|
| 登录 | Login 协议、LoginHandler/NetManager；正式服选服、加载、断线、重复登录反馈 | 开发登录和恢复可用；正式身份、顶号、长连接同步缺失 | 会话隔离测试后，实测登录→主城、断线恢复、过期及顶号；不自动抢回会话 |
| 主城 | MainCityLayer、正式服对应账号画面；入口、开放条件、资源、布局与层级 | 目前为已接入模块入口，不等于完整主城 | 同尺寸截图记录入口清单；分别标已接入、未开放、缺功能；核对返回路径和资源刷新 |

| 挂机 | BattleHandler 3005、挂机配置及正式服领取流程 | 普通计时/领取及 SuperScroll 奖励可用；加成、付费速战、掉落堆/碎片表现未完整 | 对照计时、上限、收益与随机奖励含义；领取前后资产、重复领取/重登；VIP 等差异需明确账号条件 |

## 每项修复的完成标准

每个差异记录原版路径/协议/配置行或截图、当前入口、预期行为、修复提交和复验结果。代码/配置与正式服冲突时保留两份证据并询问负责人，不凭经验改数值。

“完成”必须覆盖入口和退出、成功与失败条件、数据持久化与重复操作、规定尺寸的真实表现。资产功能需验证后端权威与断线恢复；预制体需检查脚本/UUID/动态资源与页面对应关系。列表遵守 SuperScroll，模块遵守背包职责划分，不为统一名字而重置 UUID。

按最新优先级先完成通信基础、登录与背包，背包作为迁移模板，英雄升级随后接入；每一条可运行流程接入后立即与正式服对照，不等到全部玩法恢复。网络测试与视觉对照分别记录，不能互相代替。当前不继续扩展窗口巡检，也不批量重做全部 Prefab。
