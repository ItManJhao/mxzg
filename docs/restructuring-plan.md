# 完整重做实施路线

更新：2026-11-13。实际状态只在[当前进度](development-progress.md)维护；本文决定后续顺序和完成条件，不另列一份批次进度。旧 P0–P10 详细任务及旧状态已保存在[历史路线快照](validation/restructuring-plan-history-20261113.md)，其中 HTTP 双入口、已开放升级/挂机领取及旧包数量均不能作为当前实施依据。

## 当前判断

工程与客户端维护入口已基本收敛：模块 MVC、页面自行定义、ResManager、三段显式加载、资源池、页面/Prefab 缓存、共享模态和等尺寸虚拟列表已具备。下一步不继续无目标的全仓重命名或增加管理层，发现具体问题时随功能修正。

玩法目前完成前三关主线子集及挂机只读演出，距离完整旧游戏仍有完整挂机收益、更多技能/关卡、英雄养成及其他模块的缺口。完成率不按文件数量、资源包数量或已有页面数量计算。资源清理是移除未实现入口，后续仍需按旧源码逐模块恢复。

## 接下来的执行顺序

| 顺序 | 工作 | 完成条件 |
|---|---|---|
| 1：技术收尾 | 在下一次构建授权后，集中验证目录与脚本迁移后的发布包 | 16 包归属正确，bootstrap 本地启动、effects 远程下载与原 UUID 引用有效；自动构建钩子生效。用独立环境检查三段加载、背包/英雄/挂机入口、挑战结算返回及缓存保护/闲置重开；记录本包和远程实际字节 |

| 5：后续逐模块 | 更多技能/关卡、英雄养成及其他旧系统 | 每批明确旧规则、配置、资产、协议、交互和验收范围；真实规则无法确认时标缺口并询问，不以普攻或零值替代 |

本轮只完成仓库交付和文档整理，不要求负责人再操作 Creator。下一次构建用于覆盖实际编译/打包差异，集中进行，不恢复每改一个页面就构建的流程。已验收的挂机循环、英雄对话、挑战开场、胜利/统计、历史名称外观和只读表现不安排重复重做。

当前宝箱领取、快速战斗、英雄升级、穿脱和其他模块仍未开放。三段全部由 LoadingPlan 显式配置，其他按需；不恢复全量后台加载，不增加模块资源清单。WS＋Protobuf、服务端权威、持久幂等及唯一 Model 保持。

## 后续验证与已知问题

- 真实 CDN 尚无正式地址；先保留本地样板，获得地址和相关授权后验证 HTTPS、缓存版本、失败重试、离线及发布回滚。配置内容远程签名/安装/回滚并未实现。
- 真机、原生/微信平台、长时间切页和 GPU/内存没有最新结论。先测量，再调整 LoadingPlan、缓存期限或容量，不先增加新缓存层。
- 现有虚拟列表支持等尺寸格；变高/循环列表不是当前需求。产物说明横向区域起手竖拖的父子接管需有真实问题和验证再处理。
- 清心概率、护盾、部分技能表现、大型模型裁边保留在[战斗问题表](battle-known-issues.md)；三份主城配置版本差异见[配置来源](../config/client-maincity/README.md)。不以框架整理顺手改规则或美术。
- 负责人已排除横屏和专门拆分 RemakeApp 的改造，本路线不重新安排。

## 每批工作的完成条件

1. 从当前进度、Git 与实际源码确定一批明确范围；后续继续在 hao 开发，提交、推送、合 main 分别遵循当次授权。
2. 先核实旧源码/配置，再实现数据归属、交互与生命周期；纯规则直接复用，不新增无用包装、兼容别名或第二份状态。
3. 执行与改动匹配的检查。界面、打包、性能分别记录，类型通过或资源存在不能替代画面和真实运行；资产流程使用独立测试环境。
4. 更新当前进度与相关维护说明，历史长过程归档；已验证、未验证、未开放分开写，不能把历史通过记录当作新结果。
5. 分期可玩不等于完整还原或发行完成；最终交付还需所有承诺内容、三端及运营范围的证据。
