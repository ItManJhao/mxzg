## 完成标准

验收需有源码/配置依据、正常与取消路径、重连/持久化/幂等证据，以及目标屏幕中的实际画面。编译通过、协议返回成功和Prefab存在均不足以说明已还原。资产测试使用独立环境，不用GM伪造正式流程已接通。

## 首个闭环与最终交付的区别

一个新玩家能够从启动、登录、创角/角色初始化进入主城，获得英雄、出阵、挑战主线、播放战报、领取结算、挂机领取和基础养成；退出重登数据一致。三端至少各有可安装/运行的验收包。收费发行还必须通过 P8/P9，不能把开发联调版本称为上线完成。

首个闭环：账号与角色、主城、英雄、背包、阵容、主线战斗、结算、挂机、基础召唤与养成、基础邮件。聊天、公会、跨服及复杂活动分批恢复，必须列入最终交付；如果玩法需要改规则或删减，应明确询问用户，不能以首测范围或资源已删除为理由跳过。

## 每批工作的更新规则

1. 开始前读取本文、development-progress.md 和 Git 状态，选择依赖已满足的一小组任务。
2. 完成实现、必要检查和失败处理，记录涉及的任务 ID、文件、结果和未验证范围。
3. 更新实际进度；状态有证据才升级，旧历史记录不作为最新状态。
4. 日常按已授权范围在 Creator/预览核验；需要人工编辑体验时说明具体操作，不能用自动化代签。构建另按用户要求执行。
5. 保留已有本地修改，不清库、不自动发布。提交/推送按当前任务范围执行；本次核查和文档整理不自动提交。
