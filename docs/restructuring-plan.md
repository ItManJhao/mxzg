# 实施路线

2026-11-24 更新。长期目标是逐步 1:1 恢复旧项目。七个底栏入口已有可操作的基础业务。各入口当前开放范围见[项目进度](development-progress.md)，初版目标见[产品需求](product-requirements.md)。

## 初版交付范围

| 入口 | 初版要走通的操作 |
|---|---|
| 主城 | 新号命名、赠礼、召唤、市场和个人资料均可从实际入口操作并返回，开放条件与正式服一致 |
| 英雄 | 获得英雄、查看及培养、穿脱、布阵、保存，再到战斗中使用实际属性和已接通的技能 |
| 背包 | 到账后分类查找、打开对应详情，按成长需要使用或合成，消耗和产出均可在重登后核对 |
| 战斗 | 进入已验证的连续关卡、挑战、结算、查看战报、领取通关与挂机收益，断线后恢复 |
| 副本 | 在真实等级开放大厅，查看产物，通过至少一类副本完成挑战、胜后扫荡、次数更新和到账 |
| 公会 | 查找、创建、申请、审批和退出，角色与公会成员看到一致的身份和成员数据 |
| VIP | 从第七个底栏入口查看日服对应的契约任务、等级、权益，领取真实已达成奖励 |

## 快速战斗、幻境与 VIP4 验收

| 顺序 | 实现 | 完成条件 |
|---|---|---|
| 1 · 主线快速战斗 | 日服 `QuickBattleCtr.lua` 和 `BattleHandler.quickBattleReward` 对应同一操作。基础配置为 20 级开放，每次按 7,200 秒计算挂机收益。无活动和速战特权时，普通角色当日四次报价为 0、50、100、200 钻。由服务端计算报价、扣费、发奖并保存成功次数，复用现有挂机收益规则、资产快照和奖励反馈。活动赠次和特权价依赖各自的真实资格 | 独立角色核对等级边界、四次到账、余额不足或用尽时拒绝、重复请求只计一次。上海跨日后每日次数重置，第五次成功仍计入历史累计。验证普通挂机宝箱的计时和未领收益 |
| 2 · 幻境之塔 11～30 层 | 扩展塔配置导出，按原配置编号分别保存第 10、20、30 层的领取状态，保留旧第 10 层的已领记录。[塔导出器](../tools/export_tower_rules.py) | 服务端连续挑战 11～30 层，验证精力、扫荡、失败和重登。Creator 抽验新增动作及第 20、30 层实际领奖；迁移前已领第 10 层的角色无法再次领取 |
| 3 · VIP3 升 VIP4 | 任务 101300、101400、101500、101600 分别读取主线通关 100 关、高级召唤累计 10 次、快速战斗累计 5 次、幻境之塔通关 30 层。前两项已有持久数据，后两项依赖前面两批。沿用现有 VIP 领奖协议、红点和快照。[任务配置](../client/assets/bundles/resources/config/goddessmission.json) | 同一角色逐项达标并领取，每项 40 钻，四项合计 160 钻。最后一项领完升 VIP4；重登保留余额、等级和领取状态，重试不重复发奖 |

以上数值是日服对照值。实现时核对当前导入表及服务端配置，存在分歧的规则单列确认。端到端串验使用同一隔离角色，客户端走对应玩家入口。

## 后续初版缺口

- **英雄成长。** 接续神装洗炼、宝石外部获取、符文和其余参战加成。创造法阵的限时礼包跳转依赖活动模块。[英雄成长](hero-lineup-contract.md#升星宝石与神装)
- **真人竞技场。** 核对对手阵容快照、匹配、排行榜和赛季边界，复用已接通的战斗与统计。[新手竞技场](network-contract.md#新手竞技场)
- **自然成长串验。** 用新号从命名、赠礼、召唤、布阵和首战开始，按真实等级检查大厅、公会及契约任务开放。涉及开服天数的入口使用服务端开服日。

## 主线剩余缺口

- 第 551～850 关的旧奖励表按三字段选敌会循环使用第 541～550 关的十组守军，敌方表另有 300 组备注与全局编号对应的递进守军。需负责人确认口径后，再以第 541、550、551、560、850 关核对映射，跑连续挑战、结算、六档独立通关奖励和上限边界。沿用独立测试服连续回归、Creator 抽验新增动作和关键领奖的方式。[战斗问题表](battle-known-issues.md#当前未解决) · [通关与里程碑](main-chapter-milestone.md)
- 主线守军依赖扫描只覆盖实际出场的英雄与技能。全名册仍需逐个核对技能等级、助战、先手、控制与参战输入。统计时分别列出可获得模板数、可参战模板数和已有战报可演示的技能等级数。[技能与战斗契约](hero-lineup-contract.md)

## 挂机剩余缺口

- 本机已有普通领取。快速战斗专属活动赠次和特权价格随对应资格接入，活动角色进度、兑换和到期回收随对应活动恢复。[领取事务](main-chapter-idle-settlement.md)
- 各环境配置真实开服日期及活动控制，044 发布带有效期限与兑换配置。[活动维护](idle-activity-maintenance.md)

## 上线前与技术维护

- 目标 MySQL 复验主线、挂机、里程碑、召唤等既有事务的锁、回滚、重复请求及并发。正式 CDN、真机前后台、物理弱网和异常退出分别补验。[独立环境](local-remake-workflow.md#独立-mysql2026-11-02) · [三段资源加载](staged-resource-loading.md)
- 服务端回执校验、主线与里程碑查询内的重复加锁、播放器预检随所在模块维护。旧 CampaignService、IdleService 仍有测试调用，退役前先将数据准备及重放断言迁到实际入口。现有主线结算、挂机、里程碑各自保有服务端幂等标识，统一快照和通用奖励负责各自的反馈。[架构](architecture.md#共享可信发奖)
